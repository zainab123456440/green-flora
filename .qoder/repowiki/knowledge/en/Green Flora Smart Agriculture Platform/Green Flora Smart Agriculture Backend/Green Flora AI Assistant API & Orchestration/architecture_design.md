Three-layer design inside the module: `routes/assistant.py` exposes thin FastAPI endpoints (`/api/assistant/chat`, `/transcribe`, `/speak`, `/greeting`) that validate input via Pydantic schemas, resolve authenticated/demo user context via `_resolve_user_id`, and delegate all logic to `services.assistant_service.AssistantService`. The service is the single orchestrator: it builds a system prompt from a farmer snapshot (loaded once per request by `assistant_tools.load_farmer_snapshot`), runs a streaming chat loop over OpenAI Responses API (`_run_openai`) with function tools and web search, falls back to Gemini (`_run_gemini`) on transient errors, and streams SSE events (`type=status|delta|done|error`). Tool execution is centralized in `_execute_tool`, which dispatches to pure functions in `assistant_tools.py` — weather via Open-Meteo HTTP, market prices via `market_service`, products via Supabase PostgREST queries. A shared `TOOL_DEFINITIONS` list drives both OpenAI tool payloads and Gemini `FunctionDeclaration`s. Speech (transcribe/speak) uses OpenAI audio APIs, and the greeting endpoint caches short greetings per language/time-of-day/farmer name. Dependency direction is strictly routes → service → tools; tools depend only on existing services (`farmer_service`, `field_service`, `market_service`) and external clients (`httpx`, `supabase`).
